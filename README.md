# 随记 · TempNotes

Windows 桌面临时笔记工具。WPF + WebView2 外壳，界面全部用 HTML/CSS/JS。

随手记一条，拖一拖排顺序，拖完划掉。没有账户、没有云、没有同步服务器 —— 数据就是你指定的一个文件夹。

## 功能

- **待办 + 已完成双区**，拖动排序、跨区拖动（跨区松手按方向落到本区与目标区相邻的一侧）
- **附件**：图片 / 视频 / 文档，缩略图网格、彩色标记、删除角标
- **拖文件进来**：资源管理器直接拖，落到卡片或输入框
- **拖文字 / 链接进来**：从网页、记事本、Word 选中文字或链接拖进来，落卡片上追加、落空白处新建
- **粘贴链接自动转 Markdown**：整段粘贴只是一条链接时，自动落成 `[标题](链接)`
- **回收站**：软删除，可还原，清空后物理删除
- **搜索过滤**：顶部输入框，拖动排序在筛选态下也正确
- **批量编辑**：多选、批量改色 / 删除 / 移动
- **16 套配色**（深色为主），窗口置顶 / 开机自启 / 收进托盘
- **数据目录可换**：指向 OneDrive 文件夹即可双机共用；一条笔记一个文件，删除用墓碑表达，目录一变就自动重绘
- **本地优先**：所有数据都是本地 JSON + 文件，无网络请求

## 技术栈

| 层 | 技术 |
|---|---|
| 外壳 | WPF (.NET Framework 4.8, x64) |
| 界面 | HTML + CSS + 原生 JS（无框架） |
| 内嵌浏览器 | Microsoft Edge WebView2 |
| 拖动排序 | SortableJS（forceFallback 模式） |

## 编译

需要：Visual Studio 2019+ 或 MSBuild 16+、.NET Framework 4.8 开发包、x64。

```bash
cd src2
MSBuild TempNotes2.csproj -p:Configuration=Release -p:Platform=x64 "/p:FrameworkPathOverride=$(Resolve-Path .\refs)"
```

产物在 `src2/bin/Release/随记.exe`。

> 机器上没装 .NET Framework 4.8 目标包时会报 `MSB3644: 找不到 .NETFramework,Version=v4.8 的引用程序集`，
> 上面那句 `FrameworkPathOverride` 就是让编译直接吃 `src2/refs/` 里那份引用程序集。

**关于 `src2/refs/`**：这个仓库不含它（154MB 的 .NET Framework 引用程序集）。本机编译时把
`C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.8\` 下的
`WindowsBase.dll / PresentationCore.dll / PresentationFramework.dll` 等拷进 `src2/refs/` 即可，
或者把 csproj 里的 `HintPath` 改成引用程序集的实际路径。

**前端**：`src2/web/` 是编译时的资源输入（会复制到输出目录），`web/` 是部署目录里正在跑的那份。
改完前端要两边同步，否则编译出来的 exe 带的还是旧页面。

## 数据

默认数据目录在 `%LOCALAPPDATA%\TempNotes2`（可在设置里改）。

```
notes/<id>.json     一条笔记一个文件（v2810 起）
deleted/<id>.json   删除墓碑，记录"这条在哪一刻被删了"
backup/             启动时自动备份，保留 7 份
blobs/<id>/         附件原文件
thumbs/             缩略图
settings.json       配色、置顶、开机自启等
```

**为什么一条一个文件**：双机共用一个 OneDrive 目录时，单文件 `notes.json` 是两台机器同时写同一份，
本质上是竞态。拆成一条一个文件后，冲突范围从"整个库"缩到"同一条笔记"，写盘也只写真正改过的那几条。

**合并规则**：按 `id` 比对，取 `updated` 更新的一方；`deleted/` 里有墓碑且删除时间不早于该条 `updated` 的，
两个端都会把它删掉（旧版做不到，删除会"复活"）。

**升级**：首次用 v2810 打开旧数据目录时，会自动把 `notes.json` 拆成 `notes/<id>.json`，
原文件改名 `notes.json.migrated-<时间戳>` 留档，不删。

**实时**：程序盯着数据根目录（含 `notes/`、`deleted/` 子目录），另一台改了目录，这边立刻合并重绘，不用重启；
监听万一失聪还有 1 秒兜底轮询（窗口最小化时降到 5 秒）。你正在打字、拖卡片、输入法组词时，重绘会自动推迟到松手/失焦之后。

## 版本记录

- **v2845**（2026-11-25）**两端数据不一致的根因修复**。只改 `Core/Store.cs` + 一行启动 banner，**前端零改动**（exe 与 v2844 的差别就在这三处 + banner）。
  现象：笔记本和台式机共用同一个 OneDrive 数据目录，两端显示的数据对不上（同一条笔记一边有附件一边没有、一边已完成一边未完成），
  `notes\` 里反复出现 `<id>-<机器名>.json` 冲突副本。
  ① **拉取后回写同一份 = 写放大（主因）**。`PullFromDiskCore` 采用磁盘上的版本时把 `_written[id]` 置成 `""`，
     紧接着 `WriteChanged()` 就把刚读到的文件原样重写一遍（内容与 `updated` 都没变，只有 mtime 变了）。
     两端同时开着就成了「A 读→写→同步→B 读→写→同步」的循环，OneDrive 没法合并，只能生成冲突副本。
     现在采用磁盘版本时记 `_written[id] = Signature(dn)`（与 `Load()` 的做法一致）—— 读进来的东西不再写回去。
  ② **清扫只在启动时跑**。v2844 的 `SweepConflictCopies()` 只在 `Store` 构造时调一次，运行中同步下来的副本要等下次启动。
     现在 `PullFromDisk()`（窗口激活 / 文件监听 / 每秒轮询）都先扫一遍再拉；并加了快路径（没有任何非正名文件就直接 return），
     不会每秒去读两百多个墓碑文件。
  ③ **内容不同的副本改为按 `updated` 归一**（**推翻 v2844 的「一律保留、留待人工判断」**）。以前两台各改一版时两份长期并存：
     内存里按 `updated` 谁新谁赢、磁盘上却两份都在，两端各自显示自己那份。现在副本更新就顶成正名，
     旧正名整份复制进 `notes\_conflicts\<id>-superseded-<时间>-<机器名>.json` 留档（不删、可还原）；
     副本更旧就原样移进 `_conflicts\`。顺序严格是「先留档成功、再覆盖正名」，留档失败就放弃这次归一。
  实测：① 升级即把 `33eef8fa…-xixiaoda.json`、`49d1eff9…-xixiaoda.json` 两份移出 notes，
  `Store 载入，笔记 66 条`（此前 notes 里 68 个文件，含这两份副本）；② 只改 mtime、不改内容模拟「另一端同步下来」→
  程序合并并重绘（`检测到数据目录变化：已合并并重绘（66 条）`），但**该文件没有被回写**（mtime 与 md5 原样）；
  ③ 两端升级后都载入 66 条。
  ⚠️ 冲突副本只归档不删除；要回滚某条，把 `_conflicts\` 里那份改名回 `<id>.json` 即可。
- **v2844**（2026-11-19）修链接卡的三个显示问题 + 根治「每次启动都重算一遍」。
  ① **链接卡标题不再加粗**（用户要求）。`BuildCardDisplay` 输出从 `**标题**\n[url](url)` 改成 `标题\n[url](url)`；
     纯文字标题卡（B站/小程序那种只有标题的）同步去掉包裹的 `**`。
     历史数据由新增的 `NormalizeLinkCardDisplay()` 一次性迁移（启动时跑，幂等；实测改掉 24 张）。
     ⚠️ `FixDeprecatedShortLinks()` 原来靠「找第一个 `**`」抽标题，格式一变就会抽出空标题、把卡片打成光链接，
     已改成新旧两种格式都认（第一行带 `**` 去掉包裹，不带就直接当标题）。
  ② **只粘一个地址时不再显示两遍**。`TryMakeLinkCard` 在 URL 前面没文字时拿 URL 自己当标题，
     于是卡片是「加粗的 URL」+「可点链接」两行同样的内容。现在 `BuildCardDisplay` 判定
     「标题 == 链接」时只留链接那一行。
  ③ **URL 紧贴 `**` 时星号不再漏出来**。`inline()` 先把 URL 抠成占位符，但它的字符集 `[^\s"'<>)\]]`
     没有排除 `*`，`**https://…**` 里 URL 后面那对 `**` 会被一起吞进占位符；
     粗体规则拿到时已经不成对，`balanceEmph` 只会丢弃不配对标签 → 星号原样显示、也不加粗。
     现在字符集排除 `*`（`*` 在未编码 URL 里本来就不合法），`~` 仍然允许（`https://…/~user/` 真实存在），
     只把结尾的 `~` 退回给删除线规则。
  ④ **根治「每次启动都重算一遍」**（这才是用户看到的怪现象）。根因是**只删正名、却会读副本**：
     `DeleteNoteFile` 只 `File.Delete(<id>.json)`，而加载时 `SafeFiles(NotesDir,"*.json")` 会把
     OneDrive 冲突副本 `<id>-<机器名>.json` 一起读进内存。删了笔记后副本留在 `notes\` 里，
     下次启动又被读回来 → 每次都要重新合并/迁移一遍。本机实测留下 **11 个已删笔记的孤儿副本**。
     现在四处一起改：`IdFromFileName()` 从任意文件名认 32 位 hex id（严格：前 32 位必须 hex、后面要么结束要么接 `-`，
     `我的笔记.json`/`notes.json`/`2026-11-19-工作记录.json` 都返回 null，不会误伤）；
     `DeleteNoteFile` 连同 `<id>-*.json` 副本一起清；启动时 `SweepConflictCopies()` 扫一遍
     （只处理「有墓碑的孤儿」和「与正名内容完全相同的冗余副本」，**内容不同的一律保留**并写日志待人工判断，
     移走而不是删除，落在 `notes\_conflicts\`）；`updated` 相同时**正名文件优先**（以前谁先被枚举谁赢，
     而目录枚举顺序不稳定 = 同一份数据每次显示不一样）。
     实测三种情况：完全相同副本→移出、已删孤儿→清掉、内容不同→保留+日志，全部符合预期。
- **v2842**（2026-11-19）两个修：HEIC 缩略图 + 拖入后底部提示不走。
  ① **HEIC/HEIF 图片现在有缩略图了**。原因有两层：`.heic/.heif` 不在图片扩展名表里（存成 `file`，只能给文件图标）；
     就算归成图片，原来的缩略图走 GDI+，而 GDI+ 不认 HEIC 容器（实测报「内存不足」）。
     现在缩略图三级兜底：**GDI+**（jpg/png/webp 老路子）→ **WIC**（系统装的 HEIF 解码器注册在这里，`BitmapDecoder` 直接解，按 EXIF 方向摆正）→ **系统缩略图提供程序**。
     实测 iPhone 的 `IMG_20261119_110916.HEIC`（3072×4096）出 192×256 PNG、74KB。
     老数据不用重拖：推页面时按扩展名补判一次（`EffectiveKind`），以前存成 `file` 的 HEIC 也会按图片显示并补缩略图。
  ② **底部「③ 正在解压并建立待办」不再赖着不走**。这句本来只属于微信聊天记录包（那条路由 C# 按真实条数回报、拆完自己收尾），
     但普通文件传完也会撞上它，而且没有任何人来收（`UpBatchStep` 里没发 `progStage(0)`）。
     现在：只有 `聊天记录_YYYYMMDD_HHmmss.zip` 才显示「正在解压并建立待办」，普通文件显示「已保存」后 0.8 秒收掉；
     一批传完时 C# 统一发一次 `progStage(0)`，任何路径都不会把提示留在屏幕上。

- **v2839**（2026-11-18）修「新建/拖入要等一两秒才出卡片」「斜体字满天飞、图片跑到卡片外」「批量设已办卡 4 秒」，并加拖入进度条与批量清理。
  ① **重绘里两个 O(n²)**（这才是那一两秒的真凶，后端只占 80–118ms）：`syncAllExpand()` 逐张卡「写 class → 读 scrollHeight → 写 style」，读写交替让浏览器把整张列表重排 133 遍（实测 800ms）；FLIP 位移动画也是「读 rect → animate()」交替（实测 569ms，新建时下面所有卡都要位移所以特别明显）。两处都改成**先读完再统一写**，FLIP 另外只给可视区上下各一屏的卡建动画。实测 `setNotes` 内部 802ms → 47–67ms，FLIP 569ms → 0–8ms。
  ② **斜体标签泄漏**（`_…_` 规则）会吃掉 URL 和文件名里的下划线，还会把 `<i>` 塞进 `[标题](url)` 的 url 里；标签一旦不成对，浏览器会**跨元素重开**它，实测一次泄漏出 47 个 `<i>`，把后面卡片的正文和附件全包进斜体——附件被挤成行内宽度，缩略图就跑到卡片外面去了。现在 URL 先抠出来存着、强调规则跑完再放回；下划线强调只认「两侧是空白/标点」；最后再强制标签配对。
  ③ **批量设已办卡 4 秒**：`BatchOp` 原来 101 条逐条 `SetStatus → Touch → Save()`＝101 次全量存盘；改成只改字段、最后存一次，已经是目标状态的直接跳过（顺带修掉「已完成的时间被刷新」）。
  ④ **拖入三段进度条**（位置同原提示条）：① 正在接收文件（系统把文件交给页面，无回调 → 横扫条，走 GPU 合成层，主线程卡住也在动）；② 正在传输（真实字节数，`342.1 MB / 483.5 MB`）；③ 正在解压并建立待办（真实条数，`第 7 / 22 条`）。拿不到数字的阶段绝不编造百分比。
  ⑤ **批量「清理」按钮**（批量条上「全选」右边）：不勾选，点一下把「已完成」里的全部移进回收站（回收站里能单条恢复）。
  ⑥ 单条拖入的分享文本（抖音/公众号等）当场拆成「标题 + 可点链接卡」，和微信批量那条路一致；网络补标题放后台，不挡拖入。你自己写的 markdown 链接和超长正文不动。
  ⑦ 缩略图自愈：后台生成和全量推送经常撞车（DTO 里 `thumb` 为空的那一刻正好在生成），卡片会永久停在类型图标上。现在缺图会向 C# 补要一次（每个附件每次运行最多 2 次），`<img>` 加载失败也走同一条。
  ⑧ 页面加了全局异常上报（`JS 异常 @位置 : 信息 || 栈`），单张卡片生成 HTML 抛异常也不会再拖垮整张列表（以前会停在旧 DOM 上，表现为「卡片灰了但不下移」，只能重启）。
- **v2837**（2026-11-18）加「截图识别」，并修「打勾后要停顿一下才下滑」。
  ① **截图识别**：输入框右侧多一个按钮，只在输入框为空时出现；点它进入识别模式，往里粘贴待办截图，程序调在线 OCR 把每行文字拆成一条待办。
     引擎三选一（设置 → 截图识别）：**百度智能云 OCR**（默认，免费 1000 次/月，要自己建应用拿 Key）、**OCR.space**（免注册，共享演示额度有频率限制）、**Windows 自带**（离线兜底，质量一般）。
     识别完只保留文字，不把截图本身挂成附件；不点这个按钮时粘贴图片仍是老行为（整张图作为一条待办的附件）。

## 发版清单（每次发版必做，别只打 tag）

1. 改版本号：`MainWindow.xaml.cs` 的启动 banner、`web/app.js` 的 `APPJS_VER`。
2. 编译：`src2` 下 MSBuild（见上文），确认 `随记.exe` 与 `web/` 都是新产物。
3. 留快照：`versions/v<日期>-<版本号>/`，放源码 + web + exe。
4. 打发布包：`_release/TempNotes-<版本号>/` 全量文件 + `TempNotes-<版本号>-win-x64.zip`。
5. README「版本记录」补一条：这一版改了什么、影响什么。
6. git：`git add -A` → commit → `git tag v<版本号>` → `git push origin main` → `git push origin v<版本号>`。
7. **在 GitHub 建 Release 并上传 zip**：
   `POST /repos/weiaisuyan/TempNotes/releases`（`tag_name`、`name` 写「随记 v<版本号>」、`body` 写本版说明、最新那版带 `make_latest=true`），
   再 `POST https://uploads.github.com/repos/weiaisuyan/TempNotes/releases/<id>/assets?name=TempNotes-<版本号>-win-x64.zip` 传包。
   **只 push tag 不建 Release，网页 Releases 就会一直停在旧版本**（2026-11-10 就因此停在 v2795，用户发现后才补）。
8. 两端安装最新版：笔记本 `D:\程序\TempNotes`、台式机 `C:\Users\weiai\AppData\Local\Programs\TempNotes`，装前备份 `随记.exe` 与 `web`。

## 已知限制

- 双机同用一个目录时，如果两边**同时**编辑同一条笔记，仍是"后写覆盖先写"（按 `updated` 取新）。
  v2845 起不会再让这种差异长期留在磁盘上：OneDrive 生成的 `<id>-<机器名>.json` 会在运行期被扫掉，
  按 `updated` 归一（新的顶成正名、旧的整份留档进 `notes\_conflicts\`），两端下一轮拉取就一致了。
  真要长期双机**并行写**，还是建议换 Syncthing（会生成 `*.sync-conflict` 副本，不互相覆盖）。
- **同步速度的下限在 OneDrive 和网速，不在程序**：程序侧检出并上屏是 20–30ms，但 OneDrive 把文件从一台传到另一台
  实测约 5 秒。要更快只能换同步方式（Syncthing / 局域网共享 / 只用一台）。
- **剪贴板被别的程序独占时，复制/剪切会失败**：典型是网易 UU 远程开着「剪贴板同步」（窗口类 `UURemoteClipboard`），
  `OpenClipboard` 会一直返回 `err=5`，随记写入剪贴板会提示"剪贴板被其他程序占用"。退出该程序或关掉它的剪贴板同步即可。
- 超高卡片（超过一屏）的拖动体验受几何限制：卡片顶部最多到列表底附近，再往下靠「拖出区外 → 落到末尾」
- **微信单张链接卡片直接拖仍不行**：微信发起单卡片拖拽时在系统层就没交出任何数据（实测 `dataTransfer` 里 0 种格式、0 个文件，
  拖到桌面或记事本同样什么都没掉下来）。绕法是右键消息 → 多选 → 只勾选这一张 → 拖入，微信会生成 `聊天记录_*.zip`，
  随记会按里面的 `聊天记录.txt` 自动拆成对应数量的待办；多选多条消息同理。单纯复制 → 粘贴也仍支持。
- **链接卡片的标题解析靠各平台公开接口，不保证 100%**：
  - X / 推特：走 `publish.twitter.com/oembed`，能拿到作者 + 正文摘要（实测可用）。
  - 微博：走 `m.weibo.cn/statuses/show`，能拿到作者 + 正文摘要（实测可用）。
  - YouTube：走 `oembed`；B站：走 `x/web-interface/view`；公众号/其它站点抓 `og:title`。
  - 抖音：分享页是 JS 混淆壳，抓不到正文，只能用微信里那段分享文案当标题（通常已经带了作品名和标题）。
  - 小红书 / 知乎：反爬或需登录，标题解析基本失败，会退化成原文标题。
  - 只有标题、没有 URL 的卡片（B站/小程序常见）：先按标题去 B站、YouTube 搜索精确匹配，匹配不到就生成 Bing 精确搜索链接。
- **长链会自动换短链**：先清掉跟踪参数（微信 `mpshare`/`sharer_shareinfo`、B站 `spm_id_from` 等），清完仍超过 90 字符
  就调 `tinyurl.com/api-create.php` 换短链；换失败就用清理后的原链。卡片上显示的就是这个可点链接本身。
- **聊天记录包是 0 字节时不会建卡**：微信偶尔导出空包（拖拽时内容还没生成），随记会提示「微信这次没有导出内容，请重新多选后再拖」，
  不会留下空白附件卡。
- 聊天记录包里附带的 `聊天记录内的图片、视频和文件/` 目录：会把实体**解出来挂成附件**（图片有缩略图、视频取首帧、
  文件可双击打开）。图片/视频/文件这类消息的正文留空、只显示附件本身，双击复制的是附件而不是文件名。
- **截图识别（输入框右侧按钮）**：输入框为空时出现，点一下进入识别模式，粘贴待办截图 → 每条文字生成一条待办。
  - 默认走**百度智能云 OCR**（在线，免费 1000 次/月）：到 `cloud.baidu.com` → 文字识别 → 创建应用，把 API Key / Secret Key 填进「设置 → 截图识别」。
  - 百度免费版 QPS 很低（标准版 2 次/秒），调用已做全局串行 + 1.2 秒最小间隔；撞到 `error_code 18`（QPS 超限）会自动退避重试 3 次。
  - 也可切到 **OCR.space**（免注册，共享演示额度有频率限制）或 **Windows 自带 OCR**（离线，质量一般）。
  - 识别完只保留文字；截图里如果有图片/视频/文件，只识别它们的文件名，不会把实体挂上来。
  - 不选这个模式时，粘贴图片 = 整张图作为一条待办的附件（老行为）。
- **完成/取消完成的动画顺序**：点待办圈或右键，先在本地把圈点亮、卡片进入完成态，等 320ms 动画走完才真正提交重排。
  以前是立刻提交，卡片已经往下飞了、对勾还没画出来（2026-11-18 用户反馈）。
- **链接解析在后台线程做**：拖入时先按原文落卡并立即返回，标题/短链在后台逐条补齐后再刷新界面，
  所以大包（几百 MB、几十条）拖进来不会卡住窗口，卡片会在几秒内逐条变成「标题 + 可点链接」。
- **补标题不会让列表重排**：解析完成后只调 `window.api.setNoteDisplay(id, text)` 改那**一张**卡的正文，
  不整页重渲染、不动 `UpdatedAt`、不动排序键。早期版本每解析一条就 `PushAll()` 全量重绘，
  页面被连续重建 + 跑 FLIP，用户看到的就是「待办条不断切换排序」。这是 v2838 修掉的。
- 第三方输入法（如豆包的语音输入）在 WebView2 里失效时，通常是 Windows TSF 会话卡死，重启 `ctfmon.exe` 即可，与本程序无关
